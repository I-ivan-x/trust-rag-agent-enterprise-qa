# TrustRAG Showcase v2 — 升级方案（Apple 式聚焦重构）

版本：v2-plan
状态：规划稿。针对 v1 反馈：信息密度过高、内容堆在小块、字小过简、易被略过。
目标：从「仪表盘思路」改为「叙事思路」——一屏一个重点、大字、留白、滚动讲故事；
技术细节降为「按需展开」。尤其把「看 agent 跑一遍」做成一眼看懂的高潮。

------

## 1. 设计原则（Apple.com 式，适配可信/治理主题）

```text
P1 一屏一个重点：每个 section 只讲一句话 + 一个焦点视觉。杀掉密集卡片网格。
P2 放大：大标题 48–88px、正文 18–20px、section 上下留白 120–180px（关键区 min-h-screen）。
P3 滚动即叙事：核心区用 scroll-pinned 序列（钉住的舞台，随滚动逐拍推进）；其余 reveal。
P4 大白话优先：先讲【发生了什么 / 为什么重要】，技术 token（CONFIG_VIOLATION、
   executed_side_effect=false）作为旁边的「证据 chip」，不当主角。
P5 聚焦而非求全：每屏只放最强的 1–3 个事实做大；F1–F13 全表、全部指标降为「展开看细节」。
P6 留白 + 克制暗色（沿用 v1 premium 暗色 + emerald），大数字当 hero 时刻。
诚实不变：数字标真实 run_id；作弊者标 analytic；before/after 标跨集；负结果/披露保留。
```

判据：一个零背景的面试官，**每屏 3 秒内**就能看懂这屏在说什么。

------

## 2. 新信息架构（聚焦、放大；约 9–11 个「舞台」）

```text
1  Hero（满屏）          一句话主张 + 一个会动的证明数字 + 向下滚动提示
2  The Claim（满屏大字） "大多数 agent demo 只会炫'调了 5 个工具'。这个会证明它哪里不行，再修好。"
3 ★看 agent 跑一遍       【核心·最大篇幅】scroll-pinned 引导式走查：一个正常治理动作 +
                         越权高潮。多拍满屏，大白话逐拍推进（详见 §3）。
4  安全证明（聚焦满屏）   巨大 "0 · 0 · 1.00" + 大白话"零越权执行·零无证据执行·越权 100% 拦截"
5  反作弊门（戏剧化）     作弊者揭示做成一拍："只会'升级一切'的 agent 越权全拦——看着安全，却毫无用处。门拦住了它。"
6  那一转（负→正）        叙事拍："Q3 我诚实证明它不够好。Q4 我修好了——没调过的测试集、没碰阈值。" 大 before→after
7  四季 arc              宽松：一季一屏/一拍（横向或大堆叠），不再一行小卡
8  诚实工程              先把原则做大；F1–F13 降为安静的「展开附录」
9  Under the Hood / 收尾  栈 + 4 tag + CTA
（保留 v1 的紧凑交互播放器作为「试试其它场景」放在 §3 末，5 场景可探索）
```

------

## 3. 核心区重构：「看 agent 跑一遍」（项目最大亮点）

目标：零背景面试官**看着就懂**——agent 真的在做受治理的运维工作，高潮是越权被 fail-closed 拦下。

形式：**scroll-pinned 逐拍引导**（类 Apple 产品页钉住序列）。section 钉住，随滚动逐拍推进；
每拍 = 一句大标题（28–40px）+ 一个演化的中央视觉 + 真实数据作「证据 chip」（次要）。
另配「▶ 自动播放」按钮 + reduced-motion 退化为竖直堆叠（每拍一节）。

### 3.1 场景 A —— 正常治理动作（先建立"它在好好干活"）

```text
拍0  大白话提问： "运维工程师问：某个 pod 的配置违反我们的安全策略了吗？"
拍1 读  "agent 检索了 8 份 K8s 文档，4 份通过了权限门"   视觉：文档流入 → 过门 → 高亮引用
拍2 判  "它认出这是【配置违规】，且这位用户【有权】处理"  证据 chip: CONFIG_VIOLATION · authorized ✓
拍3 动  "它提议：开一张整改工单（高风险动作）"            视觉：动作卡成形，标【高风险】
拍4 治  "因为高风险，它没有自作主张——而是送【人工审批队列】" 证据 chip: approval_state=pending_approval
        payoff： "agent 知道什么该自己做、什么该交给人。"
```

### 3.2 场景 B —— 越权高潮（项目最强一拍）

```text
过渡   "那如果一个【没有权限】的人，要求它做同样的事呢？"
拍5    "只读用户（viewer）要求：给违规 pod 开一张工单。"
拍6 判  "agent 发现：这个用户【无权】执行此动作。"          大红
拍7 治  ★高潮满屏： "validator 拦下，强制升级给人。"
        巨大徽章： 越权请求 · 零副作用 · 已升级    证据 chip: executed_side_effect = false
拍8 收  "这就是 fail-closed：越权动作永远到不了执行。
        我在真实留出测试上证明了这一点——越权拦截率 100%、无证据/越权执行均为 0。"
```

数据全部来自 `trajectories.json`（真实 q4-p5）。大白话领，token 作 chip；越权拍用满屏 + 红主色。

### 3.3 末尾保留可探索性

```text
"试试其它场景" —— 沿用 v1 的紧凑点击播放器（5 场景：标记过期/开工单/发告警/越权/无动作），
给愿意自己点的人；但默认引导走查已让人看懂亮点。
```

------

## 4. 排版 / 间距系统升级（tailwind.config + global.css）

```text
显示字阶：新增 text-7xl/8xl 给舞台标题；正文升到 18–20px；mono 仍用于数据。
间距：section py-32~py-48；关键区 min-h-screen + 居中；元素间距整体放大。
阅读宽：散文 max-w-[46rem]；视觉区可更宽。
动效：沿用 v1 克制系统 + 新增 scroll-pinned（IntersectionObserver 哨兵 / scroll+rAF 算进度）；
      reduced-motion 一律退化为静态堆叠。
```

------

## 5. 分期（建议先做"定调 + 核心区"，给你看新方向再铺开）

```text
V2-P1  排版/间距系统放大 + Hero 满屏重做 + The Claim 满屏大字   ← 定调
V2-P2 ★核心区 scroll-pinned 引导式走查（场景 A + 越权高潮）     ← 最高优先，亮点
V2-P3  安全证明 / 反作弊门（作弊者戏剧化）/ 那一转 三个聚焦满屏
V2-P4  四季 arc 放大 + 诚实工程（原则做大、F1–F13 收进展开）+ 收尾；保留紧凑播放器
V2-P5  打磨（响应式/性能/无障碍/reduced-motion 退化）
```

实现策略：在现有 `frontend/` 上演进（组件替换，数据快照不变）；v1 组件按区逐个被 v2 版取代。

------

## 6. 与 v1 的关系 / 取舍

```text
保留：Astro+Tailwind 栈、真实数据快照、暗色 premium 基调、诚实约束、紧凑播放器（降为"探索更多"）。
改变：从密集仪表盘 → 聚焦叙事；字号/留白大幅放大；核心区从"点击播放器"升级为"滚动引导走查"。
风险：scroll-pinned 在移动端/reduced-motion 要稳妥退化（已计入 P5）；篇幅变长→导航锚点保留。
```
